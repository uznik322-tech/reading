# Windows-программа «Между строк»

Portable-программа на Electron 45 для Windows x64. Установка, браузер, Node.js и сервер для запуска готовой программы не нужны. Библиотека работает без интернета; Telegram обращается к API напрямую из программы.

## Запуск

1. Распаковать `artifacts/reading-windows.zip` в обычную доступную для записи папку.
2. Открыть `reading-win32-x64/reading.exe`.
3. Нажать «Добавить книгу» и выбрать FB2 до 16 МБ.

На текущем компьютере можно сразу запускать `reading/artifacts/windows/reading-win32-x64/reading.exe`. Переносить нужно всю папку или ZIP: один exe без остальных ресурсов не запустится. Программа рассчитана на Windows 10/11 x64. Сборка не подписана платным сертификатом издателя; Windows может попросить подтвердить её запуск.

## Данные и обновления

При первом запуске рядом с exe создаётся папка `reading-data`: в ней библиотека, позиции, настройки и зашифрованные реквизиты Telegram. Это отдельная библиотека, данные браузера и Android не копируются автоматически.

Для резервной копии закрыть программу и скопировать всю `reading-data`. Не удалять и не заменять эту папку при обновлении. Чтобы обновить программу, закрыть её, распаковать новые файлы поверх старых и сохранить `reading-data`.

Токен защищён средствами Windows (Electron safeStorage / DPAPI) и привязан к учётной записи Windows. При переносе на другой компьютер книги можно перенести вместе с профилем, но бота потребуется привязать заново. Если расшифровка не удалась, нажать «Отключить бота на устройстве» и подключить его снова; книги останутся.

Не запускать программу из ZIP или защищённой системной папки. Программа должна иметь доступ на запись рядом с exe. Системные настройки, реестр и постоянные переменные окружения сборщик не меняет.

## Telegram

1. Нажать «Telegram ↗», раскрыть настройки бота на устройстве.
2. Ввести токен от BotFather и нажать «Начать привязку».
3. Открыть показанного бота, нажать «Начать», отправить одноразовый код.
4. Вернуться в программу и нажать «Проверить код».
5. Открыть книгу и нажать «Отправить в Telegram».

Можно использовать того же бота, что в PWA и APK. Во время привязки не запускать setup-bot.js на компьютере или привязку Android одновременно: они используют getUpdates. При обычной отправке это ограничение не требуется.

`.env` из проекта не входит в архив и не читается программой. Полный FB2 в Telegram не отправляется — только название, автор, процент, глава и фрагмент. Получатель фиксируется при привязке; интерфейс не может указать другой chat_id.

## Сборка из исходников

Нужен Node.js 22.12 или новее. Из папки reading:

```powershell
npm ci --cache .tools/npm-cache
npm run windows:build
npm run windows:test
npm run windows:verify
```

Electron и упаковщик установлены локально в node_modules. Исходники программы — `desktop/`, общий адаптер — `platform.js`, сборщик — `build-desktop.js`. Публичные ресурсы копируются по явному списку, без .env, инструментов Android и пользовательской библиотеки. Промежуточные сборки находятся в .tools/windows-build. Архив создаётся из чистой промежуточной сборки; существующий reading-data не включается в ZIP.

Результаты:

- `artifacts/windows/reading-win32-x64/reading.exe` и файлы рядом;
- `artifacts/reading-windows.zip` для переноса.

Папки .tools, node_modules и artifacts исключены из Git.

## Проверки и ограничения

`windows:test` запускает готовый exe в скрытом режиме с отдельным smoke-profile. Проверяет импорт и чтение тестовой книги, переход по проценту, IndexedDB, мост Windows, защищённый контекст, изоляцию Node.js и реальное шифрование Windows. Сообщения в Telegram не отправляются. `windows:verify` проверяет состав app.asar, отсутствие действующих реквизитов из .env и отсутствие личного профиля в ZIP.

Модульные тесты используют подмену Telegram и проверяют привязку личного чата, получателя, ограничение повторной отправки и ошибки защищённого хранилища. Для реальной доставки нужно отдельно настроить бота в программе. PWA и Android остаются отдельными вариантами с тем же интерфейсом; ручной перенос места выполняется сообщением в Telegram.
