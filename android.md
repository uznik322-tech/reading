# Android APK

Один интерфейс работает в PWA и в отдельном Android-приложении на Capacitor 8.5.3. APK содержит локальные HTML/CSS/JS: сервер и HTTPS-хостинг для чтения на телефоне не нужны. Telegram требует интернет, но обращается к Telegram API напрямую через Android, без сервера читалки.

## Установка на телефон

1. Передать `reading/artifacts/reading-debug.apk` на Android через USB или другой удобный способ.
2. Открыть APK в файловом менеджере телефона. Если Android спросит — разрешить установку из этого источника.
3. Запустить «Между строк» и нажать «Добавить книгу». Выбрать `.fb2` в системном окне.

Поддерживается Android 7.0 (API 24) и новее с актуальным Android System WebView. Установка и реальная работа на телефоне требуют отдельной проверки. Это подписанная отладочная сборка для личного тестирования, не публикация в Google Play.

## Telegram на телефоне

Настройки из `.env` не входят в APK и не переносятся автоматически.

1. В приложении нажать «Telegram ↗» и раскрыть «Настройки бота на телефоне».
2. Ввести токен своего бота от BotFather и нажать «Начать привязку».
3. Открыть показанного бота, нажать «Начать», отправить показанный одноразовый код.
4. Вернуться в читалку и нажать «Проверить код».
5. Открыть книгу и отправить прогресс кнопкой в диалоге Telegram.

Можно использовать того же бота, что на компьютере. Во время привязки не запускать `setup-bot.js` одновременно: оба используют getUpdates. При обычной отправке они друг другу не мешают.

Токен и chat_id сохраняются в приватных настройках приложения, зашифрованных AES-GCM. Ключ создаётся в Android Keystore и не передаётся в JavaScript. Поле токена очищается после успешной проверки. «Отключить бота на телефоне» убирает только настройки Telegram, книги остаются.

## Локальные данные

Книги, настройки чтения и позиции находятся в хранилище WebView приложения. Библиотека Chrome/PWA — отдельная: книги нужно импортировать заново. Обновление APK с той же подписью сохраняет данные. Удаление приложения или очистка его данных удаляет библиотеку и привязку бота. Автоматической резервной копии нет; Android backup отключён, чтобы зашифрованные настройки не восстанавливались без ключа.

Для переноса места между компьютером и телефоном использовать сообщение бота: отдельно загрузить ту же книгу, нажать процент внизу читалки, ввести значение и уточнить место по главе и фрагменту.

## Повторная сборка на этом компьютере

Node.js 22+, JDK 21 и Android SDK 36. Все скачанные инструменты находятся в `reading/.tools`, без системной установки и изменения постоянных переменных окружения. Папка исключена из Git.

Из папки reading:

```powershell
npm run android:build
```

Скрипт подготовит `www`, выполнит `cap sync android`, соберёт APK и скопирует результат в `artifacts/reading-debug.apk`. Первая сборка требует доступа к npm, Google Maven и Maven Central. Последующие сборки используют локальный кэш; новые зависимости могут снова потребовать интернет.

Для нового компьютера: `npm ci`, установка JDK 21 и Android SDK 36, принятие лицензии SDK, затем указание JAVA_HOME и ANDROID_HOME в текущем терминале. Например:

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'
$env:ANDROID_HOME = 'C:\path\to\android-sdk'
npm run android:build
```

SDK, Java и кэши нового компьютера также можно положить в reading/.tools. Android Studio для командной сборки не обязателен.

## Подпись и исходники

Тестовый ключ — `.tools/signing/debug.keystore`. Для обновления уже установленного APK нужно сохранить этот ключ. Если его потерять, APK с новой подписью не установится поверх старого. Не удалять приложение с книгами ради смены подписи без резервной копии оригиналов.

Ключ отладочный, с типовыми паролями Android; для публикации потребуется отдельная release-подпись. Ключ, `.env`, `node_modules`, `www`, SDK, Gradle-кэши и APK исключены из Git. В Git входят Android-проект, lock-файл npm, скрипты и общий веб-код.

`build-web.js` использует явный список публичных ресурсов и отклоняет посторонние файлы в `www`. Файл `.env` не читается при упаковке. Android получает разрешение INTERNET, но не запрашивает полный доступ к памяти: FB2 выбирается через системный Storage Access Framework.

## Проверка

```powershell
node --test
npm run android:build
npm run android:verify
```

На телефоне проверить импорт настоящего FB2, возврат к позиции после закрытия приложения, чтение в авиарежиме, смену темы/ориентации, привязку бота, доставку прогресса, отмену выбора файла и обновление APK поверх предыдущего. Прямую отправку сообщения с реального телефона нельзя подтвердить одной компьютерной сборкой.

На компьютере выполнены сборка APK, проверка подписи apksigner, проверка содержимого APK на серверные секреты, семь автоматических тестов и Android Lint без ошибок. Lint оставляет предупреждения о ресурсах шаблона и доступных обновлениях зависимостей. Нативный мост проверен с официальным JS-runtime Capacitor и подменённым Android-вызовом; физический Android и эмулятор не использовались.
